# Property Development Workflow

## End-to-end workflow

| Stage | Main outcome |
|---:|---|
| 1 | Project created |
| 2 | Project settings, roles, standards, units, and phases configured |
| 3 | Site, survey information, orientation, constraints, and investigations defined |
| 4 | Levels, grids, and reference geometry established |
| 5 | Architecture model built |
| 6 | Plans, elevations, sections, details, schedules, and 3D views reviewed |
| 7 | Annotations, specifications, drawing information, and revisions added |
| 8 | Specialist overlays added and linked to architectural elements |
| 9 | Conflicts, dependencies, and changes coordinated |
| 10 | Project phases, approvals, issues, and revisions managed |
| 11 | Sheets, drawing sets, schedules, and issue packages created |
| 12 | Stakeholder review, approval, publishing, and audit completed |
| 13 | Information exported and used for construction execution |

## Reference-informed project records

A project should be able to record information represented in the supplied references, including:

- Project address, lot, title, owner, builder, practitioners, permit and planning references.
- Building classification, floor area, estimated cost, construction type, permit conditions, inspection stages, and occupancy requirements.
- Site classification, bore locations, soil layers, fill, drainage, founding recommendations, and geotechnical limitations.
- Architectural drawing index, drawing numbers, drawing types, schedules, revisions, and issue dates.
- Structural framing, trusses, roof pitch, overhangs, spacing, roofing, tie-downs, wind classification, and component identifiers.
- Specifications for rooms, materials, tiling, fixtures, fittings, appliances, windows, doors, electrical, heating, insulation, roofing, footings, drainage, garage, and landscaping.
- Energy-rating inputs including windows, glazing, orientation, wall construction, insulation, floors, ceilings, shading, thermal loads, and rating validity conditions.

## Coordination workflow

1. A user creates or edits an element.
2. Toolboxed identifies dependent views, schedules, documents, and systems.
3. Local visual dependencies update automatically.
4. Cross-discipline dependencies are shown as coordination items.
5. Responsible users review the effect.
6. The change is approved, rejected, revised, or deferred.
7. The model, documents, and audit history are updated according to the decision.

## Construction workflow

- Convert approved model information into work packages.
- Assign tasks to responsible parties.
- Link tasks to model elements, drawings, specifications, and locations.
- Record inspections and mandatory notification stages.
- Record site progress, defects, evidence, comments, and approvals.
- Track changes against the approved issue.
- Publish updated construction information with revision history.
